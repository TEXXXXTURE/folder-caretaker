# folder-caretaker

> 文件夹自治管理 Skill：让 Agent 生成的内容有结构、可检索、可复用。
> **核心理念：AI 与 Agent 擅长产出内容，却对自己的产出没有结构感——本 skill 给 AI 的产出建立结构。**

适用于任何文件夹形态：AI 产出物文件夹、代码库、知识库、素材库、会话导出、混合杂物堆。

## 为什么存在

绝大多数人和 AI 对话时生成的文件（报告、代码、素材、导出）**没有管理规则，用户也不会主动整理**。文件散落、命名混乱、越积越乱，最终变成无法检索的垃圾堆——这是 Agent 工作流的系统性缺陷。

本 skill 解决这个问题，双功能一体：

| 功能 | 做什么 | 什么时候用 |
|------|--------|-----------|
| **A. 持续治理** | 扫描文件夹 → 在根目录生成 `00_使用规则.md` 声明（目录地图 + 放置规则 + 禁区） | 说"管理这个文件夹" |
| **B. 一次性梳理** | 扫描 → 提出整理方案 → 确认后执行（分类/移动/重命名） | 说"整理这个文件夹" |

## 机制原理：进场协议

Agent 只有在**读取、写入、删除**文件夹内容时才会与文件夹打交道。因此约束性不靠"声明文件自动注入"（那只在 cwd 恰好在文件夹内时生效），而靠**进场协议铁律**：

```
Agent 存取任何文件夹前
    → 先查根目录有无 00_使用规则.md / AGENTS.md / .agent-rules/
    → 有 → 必读必守 → 再执行操作
```

规则文件以 `00_` 前缀命名，列目录即见——**进场即读**。文件夹自治的唯一生效点，就是"Agent 点进文件夹的那一刻"。

## 安装

```bash
# Hermes / 任意支持 SKILL.md 的 agent
git clone https://github.com/TEXXXXTURE/folder-caretaker.git
# 将 SKILL.md 放入你的 agent skills 目录
```
## 触发方式

- 「管理这个文件夹 / 给这个文件夹定规则」→ 功能 A：生成 `00_使用规则.md`
- 「整理一下这个文件夹 / 这个文件夹好乱」→ 功能 B：梳理方案 + 执行
- 任何 AI 产出物文件夹、代码库、知识库、素材库、会话导出、混合杂物堆

## 类型适配

| 类型 | 识别特征 | 声明侧重 |
|------|---------|---------|
| 代码项目 | package.json / src/ / tests/ | 结构约定、构建命令、命名规则 |
| 文档输出 | .md/.docx/.pdf 为主 | 命名规则、归档规则、frontmatter 规范 |
| 素材库 | 图/音/视频多 | 分类约定、命名模板、元数据 |
| 会话导出 | 时间戳文件名、session 字样 | 归类规则、摘要索引约定 |
| 混合杂物堆 | 无主导类型 | 先分类后治理、分区放置 |

## 效果示例

对 `D:\ai生成`（散落 2 份带日期括号命名的 md 报告）运行功能 A 后：

```diff
  ai生成/
+ ├── 00_使用规则.md          ← 新增：目录地图 + 放置规则 + 禁区
  ├── RAG工业级五大维度调参全量实战报告（变量+场景+问题+决策点） (2).md
  └── 产品逆向拆解Skill 完整项目总结（含UX逆向能力·最终版）.md
```

规则文件排在最前，此后任何 Agent 存取该文件夹都会先读规则再动手。

## 禁区默认值（写进所有声明）

- 不删除用户手动创建的文件/结构
- 不重组已存在目录结构（除非用户明确要求）
- 不移动被其他程序占用的文件（应用目录）
- 应用文件夹（如 D:\软件）默认只生成声明，不做重组——用户不接受重组
